# 週刊少年ジャンプサバイバル（仮称）ゲーム仕様書

**Version:** Draft 0.2  
**Status:** MVP実装開始・仕様更新

---

## 1. ゲーム概要

### 1.1 コンセプト

プレイヤーがオリジナルの漫画を制作し、架空の週刊少年漫画誌で連載させ、その人気・掲載順位・売上・連載期間などをシミュレーションして楽しむゲーム。

漫画の設定を自由に組み合わせて作品を作り、その作品が何週生き残るか、どこまで人気を獲得するかを楽しむことを主目的とする。

### 1.2 ジャンル

- 漫画制作シミュレーション
- 連載サバイバル
- ランダムイベント
- 結果観賞型ゲーム

### 1.3 基本方針

- Webブラウザで動作するゲームとする。
- 漫画制作は選択式を基本とする。
- 自由入力は作品名・作者名などに限定する。
- 実際の漫画のストーリーを生成する必要はない。
- 作品の設定を内部パラメータに変換し、人気や売上をシミュレーションする。
- プレイヤーの操作は漫画制作時を中心とし、連載中の介入は限定的とする。
- 低コストで開発・公開・維持できる規模を目指す。
- 繰り返し遊べるリプレイ性を重視する。

---

## 2. ゲームの基本フロー

1. タイトル画面から新作漫画の制作を開始する。
2. ジャンル・世界観・主人公・作風などを設定する。
3. 完成した漫画の概要・初期評価を確認する。
4. 架空の漫画雑誌で連載を開始する。
5. 毎週のアンケート順位・掲載順位・売上などを確認する。
6. 人気変動・ランダムイベント・打ち切り危険度などを確認する。
7. 必要に応じて限定的な選択イベントに介入する。
8. 打ち切りまたは円満完結などにより連載が終了する。
9. 作品評価・称号・ランキングを確認する。
10. 作品を図鑑に保存し、次の漫画を制作する。

## 3. 漫画制作システム

### 3.1 基本仕様

漫画制作は複数のカテゴリから選択肢を選ぶ形式とする。

各カテゴリの選択内容によって作品の内部パラメータが変化する。

初期版では以下のカテゴリを実装候補とする。

### 3.2 題材・世界観

| 項目 | 選択肢の例 |
|---|---|
| ジャンル | バトル、ファンタジー、SF、サスペンス、ギャグ、スポーツ、恋愛、ホラー、日常、その他 |
| 世界観 | 現実世界、異世界、近未来、宇宙、歴史世界、独自世界 |
| 時代 | 現代、近代、中世、古代、未来、不明 |
| 舞台 | 日本、中国、北米、ヨーロッパ、アフリカ、アジア、オセアニア、中南米、宇宙、架空国家、その他 |
| 主な題材 | 学校、戦争、冒険、犯罪、スポーツ、職業、超能力、政治、その他 |

ジャンルは複数選択可能とする。

### 3.3 主人公

| 項目 | 選択肢の例 |
|---|---|
| 性別 | 男性、女性、その他 |
| 年齢 | 子供、少年少女、青年、成人、中年、老人 |
| 性格 | 熱血、冷静、天然、皮肉屋、無口、狂気、優柔不断 |
| 知力 | 低い、普通、高い、天才 |
| 強さ | 弱い、普通、強い、最強 |
| 職業 | 学生、戦士、探偵、教師、会社員、無職、その他 |
| 立場 | 主人公、悪役主人公、群像劇、主人公不在 |

### 3.4 作品の作風・構成

| 項目 | 選択肢の例 |
|---|---|
| ストーリー | 王道、ダーク、コメディ、悲劇、複雑、単純 |
| 展開速度 | 超高速、速い、普通、遅い、超スローペース |
| キャラクター数 | 少数、普通、多数 |
| 雰囲気 | 明るい、シリアス、暗い、混沌 |
| 画風 | シンプル、標準、緻密、独特 |
| 独創性 | 王道、変化球、奇抜、前衛的 |

### 3.5 作品の基本情報

- 作品タイトル
- 作者名
- 制作時の設定
- 漫画家能力・担当編集能力・総合能力
- プレイヤーによる能力配分
- 設定補正後の作品能力
- 作品の初期評価

### 3.6 漫画としての完成度・能力配分（追加仕様）

作品の人気は漫画設定だけでなく、漫画としての完成度・能力も反映する。

評価項目は以下の5項目とする。

| 評価項目 | 概要 |
|---|---|
| ストーリー | 物語の展開・内容・伏線など |
| キャラクター | 登場人物の魅力・人気 |
| 画力・演出 | 作画品質、構図、迫力、見せ場 |
| 独自性・テーマ | 新鮮さ、個性、テーマ性 |
| 構成・テンポ | 読みやすさ、展開速度、構成の安定性 |

#### 総合能力の生成

作品の総合能力は、以下の2つを乱数生成し、その合計として算出する。

**総合能力 = 漫画家能力 + 担当編集能力**

- 漫画家能力：漫画家本人の才能・制作能力
- 担当編集能力：企画、アイデア、キャラクター、ストーリー、構成などへの編集者の関与・支援能力
- 両者はMVPでは個別の項目別能力に分解しない。
- 漫画家能力・担当編集能力は作品制作時に生成し、連載中は原則固定とする。
- 具体的な乱数分布・数値範囲はゲームバランス調整時に決定する。

#### プレイヤーによる配分

生成された総合能力を、プレイヤーが上記5項目に配分する。

- 5項目の合計値は総合能力と一致させる。
- 配分時に残りポイント・合計ポイントを表示する。
- 総合能力を超える配分はできない。
- 配分をリセットできる。
- MVPでは項目ごとのミニゲームは実装しない。
- 能力配分は漫画制作時に行い、連載中の自由な再配分は原則行わない。

#### 漫画設定との組み合わせ

- ジャンル・主人公・作風などの漫画設定は、能力配分とは別に作品能力へ補正を与える。
- 設定だけで作品の実力が決まる方式にはしない。
- 能力配分と漫画設定の両方を人気・連載結果に反映する。
- ジャンルによって各能力が人気に与える影響度を変えることを検討する。
- 具体的な補正値・計算式はゲームロジック設計時に決定する。

## 4. 作品内部パラメータ

### 4.1 基本能力

作品の能力は、漫画制作時の5項目の配分値と、漫画設定による補正を基礎とする。

| パラメータ | 内容 |
|---|---|
| ストーリー | 展開・伏線・物語の完成度 |
| キャラクター | 主人公・登場人物の魅力 |
| 画力・演出 | 視覚的な魅力・迫力・見せ場 |
| 独自性・テーマ | 新鮮さ・話題性・作品の個性 |
| 構成・テンポ | 読みやすさ・展開速度・構成の安定性 |

これらの5項目を人気計算の主要な入力とする。

連載シミュレーションでは、上記5項目に加えて、以下の派生的な内部指標を使用してよい。

- 読者適性：週刊少年漫画誌の読者との相性
- 安定性：人気を維持する能力
- 爆発力：大ヒット・急上昇の可能性

派生指標の具体的な算出方法はゲームロジック設計時に決定する。

### 4.2 パラメータ算出

- 5項目の配分値を作品の基礎能力とする。
- 漫画設定の選択内容から各能力への補正を設定する。
- 選択内容の組み合わせによる相乗効果・相性補正を可能とする。
- 能力生成に乱数を使用するが、Seedによる連載結果の変動と混同しない。
- 能力値はプレイヤーに公開する。少なくとも配分画面では各項目と総合能力を確認できる。
- 制作時には評価コメントなどで作品の傾向を示す。

## 5. 連載シミュレーション

### 5.1 基本仕様

- 架空の週刊少年漫画誌1誌を対象とする。
- プレイヤー作品と複数のライバル作品が同時に連載される。
- 連載は週単位で進行する。
- 毎週の人気・アンケート順位・掲載順位・売上を算出する。
- 人気変動やランダムイベントを発生させる。
- 一定条件で打ち切り・完結判定を行う。

### 5.2 連載開始時

連載開始時に以下を決定する。

- 初期人気
- 初期アンケート順位
- 初回掲載順位
- 初期読者層
- 編集部期待度

初期人気は作品能力・乱数・編集部評価などから算出する。

### 5.3 毎週の処理

各週で以下の処理を行う。

1. 作品人気を計算する。
2. アンケート順位を算出する。
3. 掲載順位を決定する。
4. 単行本売上を更新する。
5. ランダムイベントを発生させる。
6. 打ち切り危険度を更新する。
7. 打ち切り・完結判定を行う。

### 5.4 人気変動

人気は前週の人気を引き継ぐ形式とする。

人気変動には以下の要素を使用する。

- 作品の基本能力
- 連載経過による変化
- 乱数
- ランダムイベント
- 読者層との相性
- ライバル作品の人気
- 人気の安定性

毎週完全に独立した乱数で人気が決まる方式は避ける。

Seedを変更した場合、作品の能力による基本的な成功・失敗傾向は維持しつつ、イベント・順位・人気推移などの細部が変化するようにする。

- 極めて能力の高い作品は、Seedを変えても基本的に高い人気を獲得・維持する。
- 能力の低い作品は、Seedを変えても基本的に苦戦する。
- 中程度の能力の作品は、環境・イベント・乱数による結果の差が比較的大きくなる。
- 連載枠やライバル作品などの環境要因により、作品の実力と連載寿命が完全一致しない余地を残す。

ただし、具体的な確率・係数はゲームバランス調整時に決定する。

## 6. アンケート・掲載順位・売上

### 6.1 アンケート順位

- 毎週の読者アンケート順位を算出する。
- 順位は連載作品全体の相対評価とする。
- 人気の変動を順位に反映する。
- 順位は打ち切り判定の主要指標とする。

### 6.2 掲載順位

掲載順位はアンケート順位を基礎として決定する。

ただし、アンケート順位と掲載順位は完全一致させない。

掲載順位には以下の要素を加味する。

- 編集部判断
- 新連載補正
- 巻頭カラー・記念掲載
- 特別イベント
- 人気の長期推移

### 6.3 単行本売上

単行本売上は以下の要素から算出する。

- 人気の累積
- 固定ファンの強さ
- 作品の長期的評価
- 単行本発売時の人気
- ランダムイベント

アンケート順位とは別の指標として扱う。

---

## 7. 打ち切り・連載終了システム

### 7.1 打ち切り判定

打ち切り危険度は以下の要素から算出する。

- 直近数週のアンケート順位
- 人気の下落傾向
- 単行本売上
- 連載期間
- 編集部期待度
- 雑誌全体の連載枠

一定条件を満たすと打ち切り危険度が上昇する。

危険度が高い場合でも、必ず即打ち切りになるとは限らない。

### 7.2 連載終了パターン

| 終了パターン | 概要 |
|---|---|
| 即打ち切り | 極端な低人気による短期終了 |
| 通常打ち切り | 人気低迷の継続による終了 |
| 円満完結 | 一定以上の人気と十分な連載期間 |
| 長期連載 | 長期間人気を維持 |
| 大ヒット完結 | 人気・売上ともに高水準 |
| 伝説的作品 | 極めて高い人気・売上・長期連載 |

## 8. ランダムイベント

### 8.1 ポジティブイベント

- 主人公が読者に大人気
- 必殺技が話題になる
- 人気キャラクターが登場
- 神回と評価される
- アニメ化決定
- SNSで話題になる
- 単行本売上が急増
- 読者層が拡大

### 8.2 ネガティブイベント

- 展開がマンネリ化
- 主人公が不人気
- ストーリーが難解すぎる
- 作画崩壊
- 伏線回収に失敗
- 読者から批判
- 作者の体調不良
- 休載
- ライバル作品の大ヒット

### 8.3 特殊イベント

- 編集部から路線変更を要求
- 主人公交代
- 急展開による人気爆発
- 予想外のキャラ人気
- 打ち切り寸前からの復活
- 作者の意図しない方向で作品が人気化

初期版では固定イベントと条件付き乱数イベントを基本とする。

## 9. プレイヤー介入システム

### 9.1 基本方針

連載中の操作は限定的とする。

プレイヤーは基本的に連載結果を観察するが、特定のイベントで選択肢を提示される。

### 9.2 介入例

**編集部からの路線変更提案**

- 王道展開に変更
- 現状維持
- 大胆な路線変更

選択によって作品能力・人気・安定性などが変化する。

### 9.3 介入頻度

- 毎週の介入は行わない。
- 数週に一度、または特定条件でイベントを発生させる。
- 介入しないまま連載を進行させることも可能とする。

## 15. 技術・実装方針（追加・決定事項）

### 15.1 技術構成

- プロジェクト名：`manga-survival`
- 言語：TypeScript
- UI：React
- 開発・ビルド：Vite
- 保存：localStorage
- ソース管理：GitHub
- 公開：静的ホスティング（GitHub PagesまたはVercelを想定）

MVPではバックエンド、データベース、外部APIを使用しない。

### 15.2 アーキテクチャ

- UIとゲームロジックを分離する。
- ゲームロジックは独立したTypeScriptモジュールとして実装する。
- ゲームロジックは可能な限り純粋関数とし、単体テスト可能にする。
- 1週間分の処理を `advanceWeek(state)` 相当の単一関数に集約する。
- 1週ずつ進行する場合も、一括シミュレーションの場合も同じ週次処理を繰り返す。
- ゲーム設定・バランス調整値はロジックから分離し、設定ファイル等に集約する。
- 不必要なライブラリ・過剰な抽象化を避け、MVPに必要な範囲で実装する。

### 15.3 乱数・再現性

- Seed付き乱数生成器を使用する。
- 連載開始時にSeedを生成・保存する。
- 同じSeed・同じ初期状態・同じ設定であれば、同じ連載結果を再現できるようにする。
- Seedを変更すれば別の連載結果を得られる。
- ゲームロジック内で `Math.random()` を直接使用しない。
- テストでは固定Seedを使用する。
- セーブ・ロード後も連載を再現・継続できるよう、必要な乱数状態を保存する設計を検討する。

### 15.4 データモデルの基本概念

以下のデータを分離して扱う。

- `GameData`：セーブデータ全体
- `MangaRecord`：漫画の設定・能力・基本情報
- `SerializationRecord`：漫画の連載1回分の記録（Seed・状態・結果）
- `WeeklyRecord`：週ごとの人気・順位・売上・イベント等
- `GameEvent`：発生イベント
- `SerializationResult`：連載終了時の評価・結果

1つの漫画に複数の連載記録を紐づけられる構造とする。ランキングは原則として保存データから算出し、重複したランキングデータを別途保持しない。

### 15.5 開発・実装時のCopilot利用方針

- 仕様書・決定事項を参照してから実装する。
- 機能単位で実装し、ビルド・動作確認を挟む。
- 仕様が曖昧な部分を勝手に大幅拡張しない。
- 重要な仕様変更は、実装前に理由と影響を説明する。
- TypeScriptの型を適切に定義し、`any`を安易に使用しない。
- 既存コードの変更範囲は必要最小限にする。

## 17. 開発目標

最初の完成目標は、

**「5分で漫画を制作し、数分でその連載人生を見届けられるゲーム」**

とする。

漫画の設定を考える楽しさ、連載結果を観察する楽しさ、そして次の漫画を制作する楽しさを循環させる。

複雑な経営シミュレーションではなく、漫画の創作と連載結果のシミュレーションを中心とした、短時間で繰り返し遊べるWebゲームを目指す。
